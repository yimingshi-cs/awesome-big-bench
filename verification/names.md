# Benchmark naming checks

The old list described eleven names as having “no result”. Seven have a related project, repository-name collision or handle worth flagging; for four, this pass found no exact benchmark in the inspected indexes. That is a finding about these eleven suggestions, not about the fraction of *all* benchmark names already taken.

[Search log for this round](names/field-checks-2026-11.csv). For each suggestion we searched arXiv (hyphenated, spaced, joined, and plural spellings), OpenAlex titles, public GitHub repositories and organization names, Hugging Face models/datasets/Spaces, and the open web. Exact code-host names ignore case, separators and punctuation. False positives included a paper about *over-mocked tests* for Agent-Mock and an astronomy paper about *sub-mm mock* observations for MM-Mock. Neither named a benchmark.

The log records query dates in Singapore time, returned IDs or counts, and service failures. We checked the joined and dashed .com, .org and .ai names with RDAP. For .io, a timed-out public DNS endpoint was followed by local NS queries; even an NXDOMAIN result does not establish registration availability. Google Scholar was not part of this round. A capped or failed query is never treated as zero matches.

**How to read the grid.** A cell marked **used** points to a project actually using the name (case, typography and separators can vary). It need not be an LLM benchmark: “Awesome Bench”, for example, tests HTTP frameworks. **Near** covers a related name *or* a collision in another namespace; the note identifies which. **No match** means we found no exact benchmark in the recorded searches, not that all domains or handles are available. **Partial** is for an inconclusive check. A blank cell means **not checked**. Rows and columns are naming patterns, not an inventory of all possible projects.

## The comment thread, checked against originals

- **BenchBench is already two different papers.** [Do These LLM Benchmarks Agree?](https://arxiv.org/abs/2407.13696) investigates agreement across evaluations in 2024. [Benchmarking Automated Benchmark Generation](https://arxiv.org/abs/2603.20807) evaluates generated benchmarks in 2026. [BenchBenchBench](https://github.com/emollick/benchbenchbench) in turn audits benchmark-generation evaluators. None of these names is an unclaimed suggestion.
- **Benchmark²** is the typography used here for the paper titled [Benchmark^2](https://arxiv.org/abs/2601.03986). This does **not** establish the literal shorter strings **Bench²** or **bench square** as official project names.
- **metabench is not unique either.** Compare a [sparse test of general LLM ability](https://arxiv.org/abs/2407.12844), a [metabolomics test](https://aclanthology.org/2026.acl-long.1506/), and a [meta-analysis screening benchmark](https://aclanthology.org/2026.emnlp-main.1179/). [MetaEval](https://doi.org/10.1609/aaai.v40i40.40668) is a named paper about discrimination between models. We could not identify which work a comment vaguely attributed to CMU; no affiliation was inferred from that comment.
- **Benchmarks’ Last Exam** is the name of a [live project](https://benchmarks-last-exam.com/) and [repository of benchmark reviews](https://github.com/ZekkiCat/Benchmarks-Last-Exam). It is not called *Benches’ Last Exam*, and reviewing tasks is different from releasing another exam for models.
- **Frontier-Bench** is an old name in the **Terminal-Bench 3.0** line. Compare the [maintainer’s rename diff](https://github.com/harbor-framework/terminal-bench/commit/81658c0e1b8bee0544b20c861a4bbe0e538115e0) with the [official 3.0 announcement](https://www.tbench.ai/news/terminal-bench-3-0). That is not the origin of the entire Terminal-Bench series. **FrontierRSI** is a [separate Abundant project](https://github.com/abundant-ai/frontier-rsi).
- **awesome-bench** is already the slug of an [HTTP framework benchmarking project](https://github.com/carnojs/awesome-bench). A name collision is not evidence of an LLM benchmark.
- **Embodied Last Exam** has two relevant neighbors: [Embodied **First** Exam](https://arxiv.org/abs/2611.12177) and [**Robots’** Last Exam](https://robots-last-exam.com/). Neither is an exact title match.
- **MM-Exam**, an extra grid cell, has a [normalized repository-name collision](https://github.com/yaoyongxi/MM_Exam), a [registered .com](https://rdap.verisign.com/com/v1/domain/mmexam.com), and a [plural-form Hub Space](https://huggingface.co/spaces/israfelsr/mm-exams). Do not present it as untouched; none of those alone proves an exact-match AI benchmark.

## Search receipts

[Download the query log](names/search-log.csv) for the eleven original names and the extra MM-Exam cell. Each line gives a query URL, date, and observed result; the open-web rows link to a replay of the discovery text, not an immutable search ranking. Outcome counts refer to search hits or identifiers, not benchmark counts. Positive cells outside this set cite the named project directly in [the grid data](../data/names.csv).

| Index | What was actually checked |
|---|---|
| arXiv | Advanced all-fields searches (includes title and abstract) with OR-ed phrase variants: hyphenated, spaced, collapsed, straight/curly apostrophes and selected singular/plural forms. A positive-control BenchBench query returned papers. |
| GitHub | Public repository names and organization logins, queried with dashed and compact spellings. All returned pages were scanned; case, punctuation and separators were removed to find exact slug collisions. A repository name can be reused by different owners. |
| Hugging Face | Public model, dataset and Space identifiers, queried separately. Compare the last path segment after normalizing case and separators; keyword returns like “example-model” are not matches. |
| OpenAlex, open web & news | Title searches in OpenAlex; exact/variant open-web discovery plus inspection of relevant project sites; Hacker News story-title searches as a supplemental technology news index (first 50 per query). These are not comprehensive literature searches. |
| Domains | Compact and hyphenated forms on .com, .org and .ai using registrations from the [IANA RDAP bootstrap](https://data.iana.org/rdap/dns.json). For .io that bootstrap supplied no registry endpoint; only DNS NS responses were checked. NXDOMAIN does not prove a name is unregistered. RDAP 404 means a registry returned no record at query time, not that a name can be bought. |
| Google Scholar | Direct requests for MM-Dojo and Mathematicians’ Last Exam returned HTTP 429. No Scholar conclusions; the remaining searches were not run against the blocked service. OpenAlex and arXiv are recorded separately, not counted as Scholar. |

To correct a cell, link the original project and show the spelling it uses. If it is only a similar name or an unrelated handle, say which. To propose a negative search result, include the date, the variants, the indexes actually searched, and any gaps. Do not infer scarcity from the highlighted cells.
