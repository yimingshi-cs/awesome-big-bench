# Directory input modalities

**Input** names signals supplied to the evaluated system. It is not an inventory of attachments, tools, software environments, tasks or generated outputs. Code, text tables, HTML, JSON, keyboard instructions and text tool results count as **Text**. A screenshot counts as **Image**; an actual temporal clip as **Video**; a waveform as **Audio**. **Proprioception** is reserved for direct robot sensor observations, not an arbitrary state dictionary.

“+” lists documented channels used by a benchmark across its items or official observation configurations; not every item must use all of them. “/” distinguishes separately designated alternatives, as in text-chat versus voice runs. **—** means that the entry aggregates scores rather than receiving a model prompt, or that its public record does not establish the input modality. Do not infer a visual input from a generated app, video, plot, downstream training example or a picture in a judge's interface.

## Decisions with real counterexamples

| Record | Why the label differs |
|---|---|
| ARC-AGI-1 and 2 / ARC-AGI-3 | The static datasets expose [JSON integer grids](https://github.com/fchollet/ARC-AGI); those are **Text** when supplied as serialized symbols. For the interactive benchmark, the official agents include both a [textual grid prompt](https://github.com/arcprize/ARC-AGI-3-Agents/blob/main/agents/templates/llm_agents.py) and a [rendered-image observation](https://github.com/arcprize/ARC-AGI-3-Agents/blob/main/agents/templates/reasoning_agent.py). Thus 3 lists **Text + Image**, not “interactive grid” or “Video”. |
| OSWorld / τ-bench | OSWorld pairs task instructions with [screenshot or accessibility-tree observations](https://github.com/xlang-ai/OSWorld/blob/main/mm_agents/agent.py). A text-only run is possible; screenshots are a first-class image channel. The τ benchmark's [published text and voice tracks](https://github.com/sierra-research/tau2-bench) are separate modes; **Text / Audio** begins with the voice-enabled editions, not the original customer-support suite. |
| GAIA / GDPval | These have genuine nontext inputs, not just unspecified “files”. GAIA's [source paper and appendix](https://arxiv.org/html/2311.12983) identify image, video and audio inputs. GDPval's [input assets](https://huggingface.co/datasets/openai/gdpval/tree/main/reference_files) include photos, clips and recordings **on the reference side**, distinct from the deliverables folder. Edition-specific GDPval-AA results are not used to infer the original's modalities, or vice versa. |
| BIRD / OfficeQA / TAT-DQA | A database/schema or a spreadsheet does not add “table” as a modality. [OfficeQA](https://github.com/databricks/officeqa) offers text and parsed structured document representations for agents. By contrast, [TAT-DQA §3.1](https://arxiv.org/html/2207.11871v1) supplies each page as an image and OCR words alongside the question. The extension “PDF” alone settles neither case. |
| BenchCAD / SWE-bench | [BenchCAD](https://benchcad.com/benchcad-1) includes rendered-part and textual/code tracks; the signal set is **Text + Image**, not “text / design / code”. [SWE-bench Multimodal](https://www.swebench.com/multimodal.html) adds visual issue material; ordinary issue text and source code are **Text**. |
| Video-MME / audio transcription | The [Video-MME paper](https://arxiv.org/abs/2405.21075) documents video, questions/subtitles and audio conditions; audio is not inferred for every video dataset. [ASROB](https://arxiv.org/html/2403.05530v5) explicitly combines text documentation with speech in context, unlike simple speech-in transcription tasks. |
| Computer use / agent tool calls | [HealthAdminBench](https://arxiv.org/html/2604.09937v1) has explicit screenshot and agent text inputs. [PhysicianBench](https://arxiv.org/html/2605.02240v1) uses a documented FHIR tool interface to query patient records; calling that interface does not itself supply images. |
| Robots | A low-dimensional vector is not in itself language or proprioception. [LIBERO's reference configuration](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/libero/configs/data/default.yaml), [CALVIN observations](https://github.com/mees/calvin/blob/main/dataset/README.md), [RoboCasa](https://arxiv.org/html/2406.02523), [FurnitureBench](https://clvrai.github.io/furniture-bench/docs/tutorials/furniture_bench.html), [ManiSkill2](https://haosulab.github.io/ManiSkill2-docs/concepts/observation.html), the [BEHAVIOR observation rules](https://github.com/StanfordVL/BEHAVIOR-1K/blob/main/docs/challenge/evaluation.md) and [RoboDojo](https://arxiv.org/html/2607.04434v1) identify proprioceptive inputs such as joint positions, not just an output trajectory. No other entry is marked proprioceptive merely for being “embodied”. |
| Optical music recognition / composite indexes | The [OpenScore evaluation](https://openai.com/index/gpt-6-astra/) asks the model to read written musical notation: **Image**, not the symbolic transcription it outputs, and not an audio performance. An [AA Intelligence Index](https://artificialanalysis.ai/methodology/intelligence-benchmarking) score combines results from other tests; the index has no separate model-facing input. |

The same vocabulary is enforced on curated profiles, name-map Arena references, reported-family records and every dated edition, including source rows later absorbed by a curated record. Details keep the original task-level description.
